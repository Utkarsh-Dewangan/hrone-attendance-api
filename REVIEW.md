List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |

| 1 | `compute_late_minutes` (lines 33–37) | **Grace period condition & floor bug:** Calculated `minutes = int((punch_in - start).total_seconds() / 60)` before checking `minutes > 10`. For `09:40:01` (601s elapsed), integer division produces `10`, making `10 > 10` evaluate to `False` and returning `0` instead of `10`. Also failed across midnight for overnight shifts and did not truncate instants to whole seconds. | Test with `punch_in` at `09:40:01` on shift `09:30`. Starter returned `0`, contract specifies `10`. | Evaluated raw delta seconds: strictly late if `delta_seconds > 600`. When late, return `delta_seconds // 60`. Constructed shift start on the appropriate IST shift date. |
| 2 | `compute_work_hours` (lines 40–41) | **Banker's Rounding:** Used Python's built-in `round()`, which rounds half-to-even. Violates rule R4 requiring half-up rounding. Also omitted second truncation. | Test with difference resulting in `2.525` hours. `round(2.525, 2)` produces `2.52` instead of `2.53`. | Used `Decimal` with `ROUND_HALF_UP`: `(Decimal(delta_sec) / Decimal(3600)).quantize(Decimal('0.01'), rounding=ROUND_HALF_UP)`. |
| 3 | `compute_overtime` (lines 44–48) | **Missing 30-minute threshold & overnight date bug:** Returned `max(0, minutes)` for any overtime without checking if overtime is $\ge 30$. Also parsed `date_str` as shift end date, breaking overnight shifts where shift ends the next calendar day. | Punching out 5 minutes after shift end returned `5` instead of `0`. On overnight shifts (22:00–06:00), shift end was calculated on the previous day. | Enforced $\ge 30$ minute threshold; otherwise returned 0. If `shift_end <= shift_start`, shifted `shift_end` to `date + 1 day`. |
| 4 | `health` (lines 72–74) | **Dummy readiness probe:** Returned `{"status": "ok"}` unconditionally without checking MongoDB connectivity. | Stopping MongoDB service still yielded HTTP 200 instead of 503. | Executed `client.admin.command("ping")`. On exception, raised `HTTPException(503, "Database unavailable")`. |
| 5 | `create_employee` (lines 78–86) | **Race condition & schema non-compliance:** Relied on check-then-insert `if db.employees.find_one(...)`. Concurrent requests with the same `emp_code` both inserted. `created_at` was stored as naive local datetime. Did not reject `shift_start == shift_end` with 422. Exposing internal `_id` behavior. | Concurrently post two identical employee creations. Both passed check-then-insert. Sending `shift_start == shift_end` returned 201 instead of 422. | Added database unique index on `emp_code` and handled `DuplicateKeyError` to return 409. | 6 | `list_employees` (lines 89–96) | **Off-by-one pagination & filter count defect:** Used `skip = page * page_size`, skipping page 1 documents (1–20) entirely on `page=1`. `total = db.employees.count_documents({})` ignored query filter `q`. ## Items Examined and Decided NOT to be Defects

1. **`IST = timezone(timedelta(hours=5, minutes=30))`:**
   - Examined line 25: Initial suspicion was whether external libraries like `zoneinfo` or `pytz` were required. Standard library `timezone(timedelta(hours=5, minutes=30))` is exact, lightweight, portable across platforms, and carries no daylight saving transitions (IST has no DST). Kept as defined.
2. **`history: []` initialized at punch-in:**
   - Examined line 116: Initial suspicion was whether open records without history should omit the key or store empty list. Section 3 of `DATA_MODEL.md` and sample documents confirm `history: []` is expected on initial creation and populated only during manual corrections (`PATCH`).
3. **Pydantic default values for shifts:**
   - Examined `EmployeeIn` defaults `shift_start: "09:30"` and `shift_end: "18:30"`. These match the OpenAPI specification schema default values and were preserved.
